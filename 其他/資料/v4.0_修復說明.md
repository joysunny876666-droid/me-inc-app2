# v4.0 修復說明

## 🐛 修復的問題

### 問題描述
用戶修改重複項目的「重複開始日期」為未來日期後，該項目仍然在今天顯示。

**重現步驟**：
1. 建立一個重複任務（例如：每天重複）
2. 編輯該任務
3. 將「重複開始日期」改為明天或更晚的日期
4. 保存
5. ❌ **錯誤**：任務仍然出現在今天

**預期行為**：
- ✅ 如果重複開始日期是明天，今天不應該顯示該任務
- ✅ 只有在開始日期當天及之後才顯示

## 🔧 修復內容

### 修改檔案
`modules/02_tasks.js` - `getTasksForDate()` 函式

### 修改位置
第 63-73 行

### 修改內容

#### 修改前（錯誤邏輯）：
```javascript
const taskStartDate = task.date || (task.createdAt ? task.createdAt.split('T')[0] : '1970-01-01');
if (dateStr < taskStartDate) return acc;
```

**問題**：
- 重複任務使用 `task.date`（通常為 null）或 `task.createdAt` 作為開始日期
- 沒有檢查 `recurrence.startDate`
- 導致即使設定了重複開始日期，也不會生效

#### 修改後（正確邏輯）：
```javascript
// v4.0 修復：重複任務應該使用 recurrence.startDate 作為開始日期
let taskStartDate;
if (task.type === 'recurring' && task.recurrence && task.recurrence.startDate) {
    taskStartDate = task.recurrence.startDate;
} else {
    taskStartDate = task.date || (task.createdAt ? task.createdAt.split('T')[0] : '1970-01-01');
}

// 如果查詢日期早於任務開始日期，直接跳過
if (dateStr < taskStartDate) return acc;
```

**改進**：
- ✅ 重複任務優先使用 `recurrence.startDate`
- ✅ 單次任務使用 `task.date`
- ✅ 如果查詢日期早於開始日期，任務不會出現在列表中

## 🔍 技術細節

### 修復邏輯解釋

**原始問題根源**：
`getTasksForDate()` 函式在判斷任務是否應該顯示時，沒有正確處理重複任務的開始日期。

**判斷順序**：
```
1. 檢查是否有 exceptions（例外覆蓋）
2. 確定任務的正確開始日期：
   - 重複任務 → recurrence.startDate
   - 單次任務 → task.date
3. 如果查詢日期 < 開始日期 → 不顯示
4. 繼續檢查其他邏輯（重複規則、任務性等）
```

**關鍵檢查**：
```javascript
if (dateStr < taskStartDate) return acc;
```
這一行確保任何早於開始日期的查詢都會被過濾掉。

## ⚠️ 注意事項

### 1. 已完成的歷史記錄
如果某個任務在開始日期前就已經被完成過（例如測試時），這些歷史記錄仍然會保留在 `completedHistory` 中，但不會影響任務的顯示。

### 2. 任務性（isMission）項目
任務性項目有特殊的「未完成持續顯示」邏輯，這個修復不會影響該邏輯。只要任務還沒完成，且已經到達或超過開始日期，就會顯示。

### 3. 例外覆蓋（exceptions）
如果使用 exceptions 機制覆蓋了某天的任務，即使那天早於開始日期，該例外仍然會生效（這是預期行為）。
