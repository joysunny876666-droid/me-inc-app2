## 🔧 修復內容

### 1. 修復「此項目與之後」的邏輯

**檔案**：`modules/06_calendar.js` - `updateRecurringFuture()` 函式

**關鍵修復**：
```javascript
// v4.0.1 新增：將今天及之前所有可能出現的日期都標記為已刪除
if (!freshTask.exceptions) freshTask.exceptions = {};

// 標記從創建日到昨天的所有日期為已刪除（防止舊實例殘留）
const startDate = new Date(freshTask.recurrence?.startDate || freshTask.createdAt || todayStr);
const endDate = new Date(yesterdayStr);

let currentDate = new Date(startDate);
while (currentDate <= endDate) {
    const dateKey = getLocalDateStr(currentDate);
    freshTask.exceptions[dateKey] = true;  // 標記為已刪除
    currentDate.setDate(currentDate.getDate() + 1);
}
```

**改進**：
- ✅ 現在會將舊序列的每一天都標記為已刪除（`exceptions[dateStr] = true`）
- ✅ 確保舊實例不會再出現
- ✅ 新序列從新的日期開始，完全獨立

## 🔍 技術細節

### 為什麼會有這個問題？

**舊邏輯**：
```javascript
// 只設定 endDate，但不標記已刪除
freshTask.recurrence.endDate = yesterdayStr;
```

**問題**：
- `getTasksForDate()` 函式會檢查日期是否在 `startDate` 和 `endDate` 之間
- 但如果沒有正確設定 `endDate`，或者 `exceptions` 沒有標記，舊實例仍會出現

**新邏輯**：
```javascript
// 1. 設定 endDate
freshTask.recurrence.endDate = yesterdayStr;

// 2. 標記所有舊日期為已刪除
for (let date = startDate; date <= yesterdayStr; date++) {
    freshTask.exceptions[date] = true;
}
```

**改進**：
- ✅ 雙重保險：既設定 `endDate`，又標記 `exceptions`
- ✅ 確保 `getTasksForDate()` 會正確過濾舊實例
- ✅ 新序列完全獨立，不受舊序列影響

## ⚠️ 已知限制

1. **舊數據不會自動清理**
   - 修復只對新的編輯操作生效
   - 舊的錯誤數據需要使用清理工具

2. **Exceptions 記錄會增加**
   - 每次編輯都會新增 exceptions 記錄
   - 長期使用可能會有大量 exceptions
   - 建議定期使用清理工具清理

3. **完全清空會遺失歷史記錄**
   - 如果使用「完全清空」功能
   - completedHistory 會被清空
   - 建議先備份
